# 额度推荐算法 · EDF（Earliest Deadline First）

## 核心逻辑

**目标：在所有当前可用的服务商里，找出现在最应该使用的一个，尽量减少额度重置时的浪费。**

分两步：先筛资格，再按准确的周额度重置时间排序。

## 第一步：资格过滤（Gate）

候选必须同时满足：

```
weekly_remaining_pct > 0       // 周额度还没用完
short_window_remaining_pct > 0 // 5小时或每日额度当前可用
weekly_resets_at > now          // 有效的未来重置时间
```

短窗口是硬门槛，不参与紧迫度打分。没有短窗口限制的服务商视为当前可用。

## 第二步：准确的最早重置优先（EDF）

在满足门槛的候选中：

1. 周额度重置时间最早的优先。
2. 重置时间完全相同时，周额度剩余百分比更高的优先。
3. 两者都相同时，保留用户设置中的服务商顺序。

例如：

```
Antigravity：剩余 87%，4 天后重置
Codex：剩余 100%，6 天后重置
```

推荐 Antigravity，因为它的未用额度更早清零。Antigravity 用完或短窗口暂时耗尽后，
下一次刷新会自动选择下一个最早重置的可用订阅。

## 关键设计原则

1. **准确的重置时间优先**
   不把 4 天和 6 天压缩成同一个宽泛层级。只要两个候选的重置时间不同，先用更早重置的一个。

2. **剩余量只打破相同截止时间的平局**
   两个额度同时清零时，先处理剩余较多的一个；否则剩余百分比不能覆盖更早的截止时间。

3. **短窗口只判断现在能不能使用**
   5 小时或每日额度刷新较快。它耗尽时暂时排除该服务商，恢复后重新参与 EDF 排序。

4. **缺少有效重置时间时不参与推荐**
   无法确认额度何时清零，就无法执行 EDF。界面仍可展示数据，但不能用猜测的截止时间参与推荐。

## “无推荐”状态

以下情况返回“无推荐”：

- 所有订阅的周额度都已耗尽。
- 有周额度的订阅，其短窗口当前全部耗尽。
- 没有候选提供有效的未来周重置时间。

当只是短窗口耗尽时，界面可以提示最早恢复的服务商及恢复时间。

## 额度列表顺序

额度列表以“自定义”中保存的服务商顺序为基础。周额度耗尽的候选临时移到列表末尾，
但不会改写用户保存的顺序；额度重置后，它会自动回到原来的位置。同一分组内始终保持用户顺序。

耗尽的周额度不显示空的 0% 进度条，改为“周额度已用光”，并显示精确的本地日期和时间。

## 订阅数量

Gate + EDF 不因订阅数量变化。只有一个订阅时，算法仍会判断它现在是否可用；
短窗口耗尽或缺少有效重置时间时不会强行推荐。
